Module 1

Operating-system roles and kernel services

Lab: Operating Systems uses operating-system roles and kernel services as a building block for more advanced study. Start by understanding the plain-language purpose of the idea, the vocabulary attached to it, and the kinds of questions it helps us answer. In beginner-friendly terms, this module asks: what problem does this concept solve, and why would a computing professional care about it?

At a deeper level, we connect operating-system roles and kernel services to the broader systems and infrastructure pathway. We examine the assumptions behind the concept, how it interacts with adjacent topics in Semester 3: Algorithms, Databases, and Systems, and what changes when systems become larger, faster, more distributed, or more safety-critical. Strong students should look for trade-offs, limits, and edge cases rather than memorizing a single rule.

In practice, teams apply operating-system roles and kernel services while building or improving a student information platform. The value of the topic becomes obvious when design choices need to be justified, tested, documented, and communicated to collaborators.

Code Examples

Step-by-step walkthroughs connect ideas to executable artifacts.

Inspecting Running Processes from the Shell

BASH example with explanation and expected behavior.

ps -ef | grep python

TOP_PID=$(pgrep -f "web-server" | head -n 1)
if [ -n "$TOP_PID" ]; then
  echo "Server process found: $TOP_PID"
else
  echo "Server process not running"
fi

Why This Works

  • List processes and filter them so you can focus on the service you care about.
  • Capture a process identifier in a variable for later checks or automation.
  • Use a conditional test to produce a clear status message.
  • Treat shell commands as building blocks for repeatable system inspection.

Expected Output

Shows matching processes and reports whether the target service is active.

Understanding Permissions Through a Small Script

BASH example with explanation and expected behavior.

touch report.txt
chmod 640 report.txt
ls -l report.txt

if [ -r report.txt ]; then
  echo "You can read the file"
fi

Why This Works

  • Create a file so you can observe permission changes directly.
  • Apply a specific permission mask and inspect the symbolic representation.
  • Check read access programmatically instead of guessing.
  • Connect the command output to user, group, and other access rules.

Expected Output

-rw-r----- ... report.txt\nYou can read the file
