Code Examples

Step-by-step walkthroughs connect ideas to executable artifacts.

Declaring a Scalable Deployment

YAML example with explanation and expected behavior.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: course-api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: course-api
  template:
    metadata:
      labels:
        app: course-api
    spec:
      containers:
        - name: api
          image: course-api:1.0
          ports:
            - containerPort: 3000

Why This Works

  • Describe the desired system state rather than manually starting each container.
  • Use labels so services and scaling rules can target the correct pods.
  • Declare multiple replicas to improve availability and load distribution.
  • Treat deployment files as versioned infrastructure artifacts.

Expected Output

Kubernetes manages three matching application replicas.

A Minimal Continuous Integration Workflow

YAML example with explanation and expected behavior.

name: test-and-build
on: [push, pull_request]
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm test

Why This Works

  • Attach the workflow to source control events so validation happens automatically.
  • Recreate the runtime environment consistently in a hosted runner.
  • Install dependencies cleanly to reduce “works on my machine” drift.
  • Fail early when tests do not pass before deployment is attempted.

Expected Output

Every push or pull request triggers an automated checkout, install, and test run.
