Reading and Applying Firewall Rules Carefully

BASH example with explanation and expected behavior.

sudo ufw status numbered
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

Why This Works

  • Inspect current policy before making changes to avoid accidental lockouts.
  • Open only the ports that match a real service need.
  • Differentiate protocol and port so the rule matches the intended traffic.
  • Treat rule changes as operational changes that should be documented and reviewed.

Expected Output

Displays current rules and enables secure defaults for remote administration and HTTPS.

A Minimal Continuous Integration Workflow

YAML example with explanation and expected behavior.

name: test-and-build
on: [push, pull_request]
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm test

Why This Works

  • Attach the workflow to source control events so validation happens automatically.
  • Recreate the runtime environment consistently in a hosted runner.
  • Install dependencies cleanly to reduce “works on my machine” drift.
  • Fail early when tests do not pass before deployment is attempted.

Expected Output

Every push or pull request triggers an automated checkout, install, and test run.
