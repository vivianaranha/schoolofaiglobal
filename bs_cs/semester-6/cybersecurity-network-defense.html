Reading and Applying Firewall Rules Carefully

BASH example with explanation and expected behavior.

sudo ufw status numbered
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

Why This Works

  • Inspect current policy before making changes to avoid accidental lockouts.
  • Open only the ports that match a real service need.
  • Differentiate protocol and port so the rule matches the intended traffic.
  • Treat rule changes as operational changes that should be documented and reviewed.

Expected Output

Displays current rules and enables secure defaults for remote administration and HTTPS.

Understanding Permissions Through a Small Script

BASH example with explanation and expected behavior.

touch report.txt
chmod 640 report.txt
ls -l report.txt

if [ -r report.txt ]; then
  echo "You can read the file"
fi

Why This Works

  • Create a file so you can observe permission changes directly.
  • Apply a specific permission mask and inspect the symbolic representation.
  • Check read access programmatically instead of guessing.
  • Connect the command output to user, group, and other access rules.

Expected Output

-rw-r----- ... report.txt\nYou can read the file
