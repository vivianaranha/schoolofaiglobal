Module 1

Advanced addressing and subnet design

Lab: Computer Networks uses advanced addressing and subnet design as a building block for more advanced study. Start by understanding the plain-language purpose of the idea, the vocabulary attached to it, and the kinds of questions it helps us answer. In beginner-friendly terms, this module asks: what problem does this concept solve, and why would a computing professional care about it?

At a deeper level, we connect advanced addressing and subnet design to the broader systems and infrastructure pathway. We examine the assumptions behind the concept, how it interacts with adjacent topics in Semester 4: Software Development and Networking, and what changes when systems become larger, faster, more distributed, or more safety-critical. Strong students should look for trade-offs, limits, and edge cases rather than memorizing a single rule.

In practice, teams apply advanced addressing and subnet design while building or improving a student information platform. The value of the topic becomes obvious when design choices need to be justified, tested, documented, and communicated to collaborators.

Code Examples

Step-by-step walkthroughs connect ideas to executable artifacts.

Checking Reachability and Name Resolution

BASH example with explanation and expected behavior.

ping -c 4 example.com
nslookup example.com
traceroute example.com

Why This Works

  • Ping verifies basic reachability and round-trip time.
  • Name resolution tools confirm whether the domain maps to the expected address.
  • Traceroute reveals where traffic moves hop by hop.
  • Together these commands form a first-pass troubleshooting routine.

Expected Output

Returns latency, DNS information, and path details for the destination host.
Try It Yourself: Change one variable, constraint, or input assumption and predict how the output should change before you run it.

Reading and Applying Firewall Rules Carefully

BASH example with explanation and expected behavior.

sudo ufw status numbered
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

Why This Works

  • Inspect current policy before making changes to avoid accidental lockouts.
  • Open only the ports that match a real service need.
  • Differentiate protocol and port so the rule matches the intended traffic.
  • Treat rule changes as operational changes that should be documented and reviewed.

Expected Output

Displays current rules and enables secure defaults for remote administration and HTTPS.
Try It Yourself: Change one variable, constraint, or input assumption and predict how the output should change before you run it.
