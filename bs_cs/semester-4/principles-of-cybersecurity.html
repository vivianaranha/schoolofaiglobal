Learning Outcomes

By the end of this subject, a self-paced learner should be able to do the following with confidence.

  • Explain threats, vulnerabilities, and risk framing within realistic principles of cybersecurity scenarios.
  • Apply confidentiality, integrity, and availability within realistic principles of cybersecurity scenarios.
  • Analyze malware, phishing, and social engineering within realistic principles of cybersecurity scenarios.
  • Design passwords, authentication, and authorization within realistic principles of cybersecurity scenarios.
  • Evaluate cryptography concepts and secure communication within realistic principles of cybersecurity scenarios.
  • Interpret network security fundamentals within realistic principles of cybersecurity scenarios.
  • Implement web security and application attack surfaces within realistic principles of cybersecurity scenarios.
  • Compare secure coding and least privilege within realistic principles of cybersecurity scenarios.
  • Troubleshoot incident response fundamentals within realistic principles of cybersecurity scenarios.
  • Connect cyber law, ethics, and professional responsibility within realistic principles of cybersecurity scenarios.

Module 1

Threats, vulnerabilities, and risk framing

Principles of Cybersecurity uses threats, vulnerabilities, and risk framing as a building block for more advanced study. Start by understanding the plain-language purpose of the idea, the vocabulary attached to it, and the kinds of questions it helps us answer. In beginner-friendly terms, this module asks: what problem does this concept solve, and why would a computing professional care about it?

At a deeper level, we connect threats, vulnerabilities, and risk framing to the broader security pathway. We examine the assumptions behind the concept, how it interacts with adjacent topics in Semester 4: Software Development and Networking, and what changes when systems become larger, faster, more distributed, or more safety-critical. Strong students should look for trade-offs, limits, and edge cases rather than memorizing a single rule.

In practice, teams apply threats, vulnerabilities, and risk framing while building or improving a student information platform. The value of the topic becomes obvious when design choices need to be justified, tested, documented, and communicated to collaborators.

Code Examples

Step-by-step walkthroughs connect ideas to executable artifacts.

Understanding Permissions Through a Small Script

BASH example with explanation and expected behavior.

touch report.txt
chmod 640 report.txt
ls -l report.txt

if [ -r report.txt ]; then
  echo "You can read the file"
fi

Why This Works

  • Create a file so you can observe permission changes directly.
  • Apply a specific permission mask and inspect the symbolic representation.
  • Check read access programmatically instead of guessing.
  • Connect the command output to user, group, and other access rules.

Expected Output

-rw-r----- ... report.txt\nYou can read the file

Reading and Applying Firewall Rules Carefully

BASH example with explanation and expected behavior.

sudo ufw status numbered
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

Why This Works

  • Inspect current policy before making changes to avoid accidental lockouts.
  • Open only the ports that match a real service need.
  • Differentiate protocol and port so the rule matches the intended traffic.
  • Treat rule changes as operational changes that should be documented and reviewed.

Expected Output

Displays current rules and enables secure defaults for remote administration and HTTPS.

Project Objective: Synthesize the most important ideas from Principles of Cybersecurity into one coherent, evidence-based artifact.

Scenario: You are advising a small team that needs to apply principles of cybersecurity to a realistic problem with clear constraints and measurable outcomes.

Requirements

  • Use at least three major topics from the course and explain why each one matters.
  • Create a concrete artifact such as a program, design, model, report, experiment, or architecture proposal.
  • Include testing, evaluation, or reflection criteria so quality can be judged transparently.
  • Document assumptions, trade-offs, and future improvements.

Step-by-Step Build Plan

  1. Choose a realistic problem statement and define what success looks like.
  2. Break the work into milestones tied to specific course concepts.
  3. Build and review the core artifact iteratively rather than all at once.
  4. Evaluate the result with evidence such as tests, traces, feedback, or metrics.
  5. Package the final deliverable with documentation and a presentation-ready summary.

Deliverables: A final artifact, short technical report, demonstration summary, and evaluation evidence for Principles of Cybersecurity.

Rubric

  • Problem framing and relevance
  • Correct use of course concepts
  • Technical quality or analytical rigor
  • Documentation and communication clarity
  • Reflection, testing, and improvement planning
