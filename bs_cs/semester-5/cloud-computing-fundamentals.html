Containerizing a Small Web Service

DOCKERFILE example with explanation and expected behavior.

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]

Why This Works

  • Choose a lightweight base image that already includes the runtime you need.
  • Set a working directory so later instructions remain consistent.
  • Copy dependency manifests first to improve rebuild performance through caching.
  • Expose the service port and define the startup command for deployment.

Expected Output

Builds an image that installs dependencies and starts the app on port 3000.

Declaring a Scalable Deployment

YAML example with explanation and expected behavior.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: course-api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: course-api
  template:
    metadata:
      labels:
        app: course-api
    spec:
      containers:
        - name: api
          image: course-api:1.0
          ports:
            - containerPort: 3000

Why This Works

  • Describe the desired system state rather than manually starting each container.
  • Use labels so services and scaling rules can target the correct pods.
  • Declare multiple replicas to improve availability and load distribution.
  • Treat deployment files as versioned infrastructure artifacts.

Expected Output

Kubernetes manages three matching application replicas.
