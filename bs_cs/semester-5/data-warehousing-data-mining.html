Creating Related Tables with Primary and Foreign Keys

SQL example with explanation and expected behavior.

CREATE TABLE students (
    student_id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    cohort TEXT NOT NULL
);

CREATE TABLE enrollments (
    enrollment_id INTEGER PRIMARY KEY,
    student_id INTEGER NOT NULL,
    course_code TEXT NOT NULL,
    grade TEXT,
    FOREIGN KEY (student_id) REFERENCES students(student_id)
);

Why This Works

  • Give each table a primary key so rows can be identified uniquely.
  • Use a foreign key to connect enrollment rows back to the correct student.
  • Mark essential columns as NOT NULL to prevent incomplete records.
  • Think about how structure choices affect data quality before inserting data.

Expected Output

Two related tables are created successfully.

Combining Data with a Join and Aggregation

SQL example with explanation and expected behavior.

SELECT s.name, COUNT(e.course_code) AS courses_taken
FROM students s
LEFT JOIN enrollments e
    ON s.student_id = e.student_id
GROUP BY s.student_id, s.name
ORDER BY courses_taken DESC;

Why This Works

  • Start from the student table because every result row should represent a student.
  • Use a LEFT JOIN to keep students even if they currently have zero enrollments.
  • Aggregate by student so repeated enrollment rows become one summary row.
  • Sort the final result to make comparison easier for users or analysts.

Expected Output

Returns each student name alongside the number of enrolled courses.
